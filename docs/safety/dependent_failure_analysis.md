# Dependent-failure analysis checklist

Document ID: DFA-LRS-001, revision 0.1 (roadmap milestone 5, item 3).

Lockstep is worth only as much as the two cores fail independently, and the
comparator, permit and supervisor paths are trusted to be independent of what
they check. This checklist lists every shared resource and common influence in
the design, what the design does about it, the evidence, and what is still
open. It is a checklist for a target, not a completed analysis: the target,
its environment and an independent review are still to come.

Status words: **Mitigated** the design addresses it and the named evidence
shows it. **Partial** addressed in part. **Open** not addressed. **Target**
can only be settled for a chosen device and board.

## Shared resources and common influences

| ID | Initiator | Affects | Design measure | Evidence | Status |
|----|-----------|---------|----------------|----------|--------|
| DF-01 | System clock: glitch or disturbance hitting both cores in the same cycle | Both cores alike | Core B runs two clocks behind core A, so the same disturbance meets different work in each | `tb_temporal_diversity`; `tb_soc_lockstep` (both buses or read data glitched in one cycle are caught); campaign sites 17 and 20 | Mitigated in simulation, with a measured gap: the same flip in both cores' register writes hit a dependent `lui` and `addi` writing one register, and both cores ended with the same wrong value (1 of 12 trials). Different work is not always different state. Candidates: a hardware retirement comparator, which saw it, or a longer or varying offset |
| DF-02 | System clock stops | Everything on `clk_i` | `clock_monitor`, on the independent watchdog clock, reports it within two windows of 256 watchdog clocks and holds the SoC in reset; the watchdog resets the SoC as a second line; the reset holds the outputs safe without `clk_i` | `tb_clock_monitor`; `tb_soc_watchdog`; HSI 8.3; FMEDA FM-24 | Mitigated in simulation |
| DF-03 | System clock frequency drift | Both cores alike, the UART and CAN timing | `clock_monitor` latches a fault when the rate is more than the tolerance (25 % by default) from nominal | `tb_clock_monitor`; FMEDA FM-24 | Mitigated in simulation for drift beyond the tolerance; drift inside it is not a fault, and the CAN and UART bit timing need their own margin |
| DF-04 | Watchdog clock lost | The watchdog | An external supervisor is assumed | HSI WD-04 | Open (board requirement) |
| DF-05 | Reset: one synchroniser for both cores | Both cores alike | One shared synchroniser, deliberately, so the cores leave reset on the same edge; core B's reset is delayed by the two-clock skew | `tb_soc_reset_network`; campaign: synchroniser upsets restart the SoC with outputs safe | Mitigated (a spurious reset is fail-safe), but not reported: FM-21 |
| DF-06 | Power: supply droop or loss | Everything | None in the RTL | | Target: brown-out detection and the board supervisor |
| DF-07 | Shared response data, the fabric to both cores | Both cores alike, so lockstep cannot see it | ECC covers the data while in the RAM; even parity taken from each slave's data before the selection, carried to both cores (through core B's delay line) and checked at each in every clock, trips the comparators on a mismatch (HSI 8.6, TSR_BUS_002) | Campaign seed 2026: every effective transient flip (12) and stuck bit (4) detected; `tb_soc_fabric`; BUS-P7 | Mitigated in simulation (FM-11). Not covered: faults inside a register slave, the fabric's target register, an even number of flipped bits |
| DF-08 | Shared bus decode and response control | Both cores alike | Formal proof of the intended behaviour | `docs/verification/formal.md` (BUS-P1 to BUS-P6) | Partial: proves the design, not a faulted decoder (FM-12) |
| DF-09 | Shared memory initialisation | Both cores read the same RAM | All-zero is a valid ECC word on an FPGA; an ASIC must clear the RAM first | HSI section 5; `tb_ecc_data_ram.memory_starts_as_zeros_with_no_errors` | Target (ASIC clearing not designed) |
| DF-10 | One boot image for both cores | Both cores alike | The image is generated by one script for both IMEMs; a wrong image runs identically on both | `check_fixtures.py` (image matches its generator) | Open: an image error is a common-cause software fault, outside lockstep's reach |
| DF-11 | Instruction decode of the same NEORV32 RTL | Both cores alike (systematic) | None: the cores are identical by design (R4.3 makes this explicit) | `rtl/soc/lockstep_core.vhd` | Accepted: lockstep targets random hardware faults, not design faults. Diverse cores are a release decision in the roadmap |
| DF-12 | Synthesis merging the two cores or the delay line, or re-encoding the safety state registers | Comparator, self-test, delay line | `fsm_encoding none`, `dont_touch`, `-fsm_extraction off`; the build stops if the flip-flop counts drop | `docs/verification/synthesis.md`; `fpga/arty_a7_100t/build.tcl` checks | Partial: checks written, no build has run (Vivado lists no devices) |
| DF-13 | FPGA configuration memory upset | Any logic, possibly both cores' routing | None in the RTL | | Target: configuration scrubbing (e.g. SEM IP) and its interval |
| DF-14 | Placement: both cores and the comparator in neighbouring logic | Physical common cause (local radiation, heat) | None | | Target: floorplan separation, if the assessment needs it |
| DF-15 | Comparator, permit and actuator-safe output share one path | Detection and reaction both | Two comparators with their own state and a latched disagreement (`dual_comparator`); each one's state and fault latch protected by encoding and an illegal-state check; the startup self-test checks both. Comparator B has its own reset synchroniser (the resets are compared, and a reset of one cannot clear a disagreement), its own delay line for core A's bus and its own injection point for core B's; the shared clock is monitored (DF-02, DF-03) | Formal CMP properties; `tb_dual_comparator_faults`; `tb_soc_lockstep`; `docs/verification/diagnostics.md` | Partial: the comparators still share the reset pin, the buses before the copies split, and the clock, and the actuator-safe line is read back with a second channel beside it (FM-22, TSR_ACTUATOR_001) |
| DF-16 | Supervisor and watchdog share the system clock domain for the bus side | Watchdog kick path | Clock-domain crossing with handshakes; the counter is on the watchdog clock | `tb_watchdog_supervisor` | Mitigated in simulation |
| DF-17 | Output pins after the comparator | Actuator, CAN, UART | Actuator: a read-back and a second channel of opposite polarity (`actuator_monitor`); CAN: the protocol's bit monitoring and CRC, and end-to-end protection at the receiver (AoU-05); UART: diagnostic only, not safety-related in the reference item | `tb_actuator_monitor`; `tb_soc_lockstep`; campaign | Mitigated in simulation for the actuator; CAN by the protocol and the item; UART accepted |

## Tool confidence

Each tool the evidence relies on, its version, what it is used for, and the
confidence argument. None has been qualified; the column says what an
assessment would need.

|------|---------|-----|----------------------|--------|
| GHDL | 4.1 (CI), 6.0 (local) | Simulation, lint, synthesis front end for formal | A simulation or synthesis bug that passes a wrong design | Two versions agree on the regression; mutation shows the tests detect seeded errors. Not qualified |
| `sim/run.py` with `tb_pkg` | In this repository | Test runner and checks | A test reported pass that did not run, or a failed check that does not fail the test | A test passes only on its own `TB PASS` line; `tb_pkg_check` runs a failed check, an assertion, a hang, an unknown test and a force on every run and requires each to be reported as such |
| VSG | 3.35.0 | Style | None that affect function | Not safety-relevant |
| YoWASP Yosys, SymbiYosys, Z3 | 0.71, z3 5.4.1 | Formal proofs | A false proof | Broken-RTL runs check that each proof fails when it should (`run_formal.py --broken`); cover tasks show each antecedent is reachable |
| Python generators | 3.11 (CI), 3.12 (local) | Firmware image, CAN reference frames, register map | A wrong fixture that the RTL then matches | Generators are independent of the RTL; `check_fixtures.py` checks they still match their outputs |

Build checks written; no build: the installed licence offers no parts |

## Assumptions to settle with a target

1. The item, its safety goals and the FTTI are not defined (milestone 5, item 1).
2. The external safe state and who removes power from the actuators.
3. The board supervisor: watchdog clock loss, brown-out, and read-back of
   `actuator_safe_o`.
4. Configuration memory protection and its scrubbing interval.
5. Whether diverse cores are needed against systematic faults (DF-11).
