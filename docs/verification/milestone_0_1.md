# Milestones 0 and 1: evidence record

This records what the patch series for milestones 0 and 1 of
`docs/ROADMAP.md` changed, how each change was verified, and what is still
open. Everything here is RTL simulation evidence, plus a GHDL synthesis smoke
test. Nothing here is formal, gate-level, FPGA or bench evidence.

- **Base:** `73c0afa` on `main` (the roadmap commit, whose RTL equals the
  reviewed baseline `102de394aa48aecc68018f505aa8057e724e35fc`)
- **Branch:** `m0-m1-fault-containment`, local, not pushed
- **Date:** 2026-11-12

The fabric tests ran against the RTL of `9616449` with the new firmware and
benches, from a short-path copy of the tree, because Windows path limits broke
VUnit's result files in a deeper scratch directory.

Tests added as coverage, which already passed before the fix:

- `tb_soc_lockstep.lockstep_trip_in_a_can_frame_goes_recessive_and_drops_the_frame`:
  CAN was already contained. The test pins that down at the top level.
- `tb_soc_lockstep.lockstep_trip_with_mie_and_meie_masked_is_contained_without_an_interrupt`:
  the old firmware never set MEIE, and containment never used MEI. The test
  checks that MEI is pending but masked at both cores, that no interrupt is
  taken, and that the pins, the gate and the RAM are safe regardless.

Tests that need a port or entity that did not exist before:
`tb_lockstep_illegal_state.registered_fault_rises_at_the_edge_after_a_mismatch`
(`fault_o`), all of `tb_soc_bus_fabric` (`soc_bus_fabric`), and
`tb_uart_abort.one_clock_gate_drop_discards_the_byte_waiting_too`, added after
the mutation sample (section 6).

### Behaviour that changed on purpose

| Change | HSI | Existing test updated |
|--------|-----|-----------------------|
| `nmi_fault_o` and MEI come from the registered fault, so the pin rises at the edge after an ECC fault rather than in the same delta | FLT-01 | `tb_soc_ecc.two_stuck_bits_lock_the_soc_within_the_ftti` now requires no pin in the detection cycle and the pin at the next edge |
| Unmapped addresses end in ERR | BUS-08 | None: no existing test read an unmapped address through a core |
| The firmware enables MIE only after its RAM test, and steps past access faults | FLT-02 | None: every firmware test still passes |

That is the baseline's 194 tests in 35 benches, all still passing, and 32 new

first-party or NEORV32 sources.

## 5. Synthesis smoke test

GHDL 6.0.0 `--synth` of `top_automotive_soc` with `-gg_boot_mode=2` and the
test image (`/c/GIT/mt/synth.sh` in the session, the same phases as
`run.py --lint`) finished without errors in about 2 s and wrote a 41,058-line
netlist. It contains both CPU instances (`i_cpu_master`, `i_cpu_checker`), the
RAM as a 32,768-entry array of 72-bit words, and `soc_bus_fabric`. The 26
warnings are about the unused `requirement_id` attributes. `run.py --lint`
synthesises every block and the SoC in boot mode 0 on every run. This shows
only that the front end accepts the design. Mapping, timing, preserved
redundancy and hardware behaviour need roadmap milestone 3.

## 6. Mutation

The harness defines 412 mutants. A full campaign was not run. A
targeted sample of the 47 mutants on the changed and new rules ran in three
shards on `cd7a7c2`:

| Result | Count |
|--------|-------|
| Killed on `cd7a7c2` | 45 |
| Survived on `cd7a7c2` | 2: `uart: pending byte kept while the gate is closed`, `uart: safety gate ignored on write` |
| Those two, rerun after `4e63a95` | Both killed (`tb_uart_abort`, `tb_soc_periph_decode`) |

The first survivor exposed a missing test, a gate dropped for exactly one clock
with a byte waiting. The second had become an equivalent mutant, because the
new discard branch blocks a gated write before the write's own gate term, so
its pattern now removes both. Mutant patterns whose code moved were re-pointed
to keep their meaning, for example the read-data and acknowledge mutants that
named the old OR and `r_bus_ack`, which now name `soc_bus_fabric`. 26 mutants
were added for the new rules. The other 365 were not rerun: they still apply
(`--check`), but their kill status after this series rests on the historical
campaign, so a full campaign is due before a release.

## 7. Open items and blockers

| Item | Status |
|------|--------|
| R0.1 Windows `--workdir` patch | Investigated, not narrowed. It drops `--workdir` on every platform, so GHDL writes library files into `sim/`. Narrowing it to Windows would move CI's libraries, and needs a CI run to check. Two concurrent runs in one directory are therefore not supported |
| R0.1 GHDL 4.1 | Not run locally. The WSL toolchain recorded earlier was gone, and CI is the maintainer's to trigger |
| R0.3 warning provenance | Counted per run in the CI summary. No baseline of accepted warnings exists yet |
| R1.3 MIE observation | MEIE is checked through NEORV32's `irq_buf`. `mstatus.MIE` sits in a record local to the CPU and cannot be named from a testbench, so MIE=0 rests on the firmware's structure, which enables it only after the RAM test |
| R1.4 watchdog clock loss | Open target requirement (HSI WD-04): an independent supervisor on the board |
| HSI section 6 | The 1024-clock power-on reset and the ECC init step are not in RTL |
| CYC, CTI, TAG | Not compared (HSI BUS-12). Valid for the pinned configuration, which issues single accesses only |
| Shared-response faults | A wrong response that both cores receive agrees at both compare points. Integrity checks on decode and read data are roadmap R2.3 |
| Formal, trace, FPGA, FMEDA | Roadmap milestones 2, 3 and 5 |
